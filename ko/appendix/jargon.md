# 부록 B 현장 용어

소프트웨어 팀의 일상 대화에는 한국어에 영어 용어가 섞이는 일이 흔합니다. 예를 들어 "PR 올리기 전에 rebase 한번 해 주세요". 팀에 막 들어온 사람은 처음 들으면 무슨 말인지 몰라 어리둥절하곤 합니다.

이 부록은 팀에서 자주 듣는 표현을 예문과 함께 모았습니다. 팀마다 습관이 조금씩 다르지만, 여기서는 흔히 쓰는 표현을 정리했습니다. 정식 정의는 [부록 A 용어집](glossary.md)을 참고하세요.

---

## 일상적인 커밋

| 표현 | 뜻 | 예문 |
|---|---|---|
| 커밋해 두다 | 지금의 변경을 하나의 버전으로 기록한다 | "한 단락 끝날 때마다 커밋해 두세요. 하루 종일 쌓아 두지 말고요." |
| 스테이징하다 | 변경을 스테이징 영역에 넣는다. 즉 `git add` | "버그 수정한 파일만 스테이징하세요. 디버그 출력은 빼고요." |
| 작업 트리가 더럽다 | 커밋하지 않은 변경이 있다(dirty) | "작업 트리가 더러우니까 커밋이나 stash하고 브랜치를 바꾸세요." |
| 깨끗하다 | 커밋하지 않은 변경이 하나도 없다(clean) | "`git status`가 깨끗해졌으니 바꿔도 돼요." |
| 커밋 해시 | 커밋 번호. 보통 앞 7글자만 말한다 | "버그 알릴 때 커밋 해시 붙여 주세요. 앞 일곱 글자면 충분해요." |
| 메시지를 제대로 쓰다 | 커밋 메시지에 무엇을 왜 바꿨는지 쓴다 | "`fix`만으로는 몰라요. 메시지를 제대로 써 주세요." |

## 브랜치와 병합

| 표현 | 뜻 | 예문 |
|---|---|---|
| 브랜치를 따다 | 지금 커밋에서 새 브랜치를 만든다 | "이 기능은 브랜치 따서 하세요. main 바로 건드리지 말고요." |
| 넘어가다, 바꾸다 | 다른 브랜치로 전환한다 | "main으로 넘어가서 최신으로 pull 받은 다음 브랜치를 따세요." |
| 머지하다 | 브랜치를 `main`에 병합한다 | "테스트 끝나면 main에 머지하세요." |
| main을 받아오다 | `main`의 새 커밋을 내 브랜치에 병합해 따라잡는다 | "브랜치가 많이 뒤처졌으니 먼저 main을 받아오세요." |
| rebase 한번 하다 | 내 커밋을 최신 `main` 뒤에 다시 붙인다 | "PR 올리기 전에 rebase 한번 하면 기록이 깔끔해져요." |
| 컨플릭트를 풀다 | 병합할 때 생긴 충돌을 해결한다 | "두 PR이 같은 파일을 건드렸으니, 나중에 머지하는 사람이 컨플릭트를 푸세요." |
| 빨리 감기로 넘어가다 | 병합이 브랜치를 앞으로 옮기기만 한다(fast-forward) | "main에 새것이 없으니 그냥 빨리 감기로 넘어가요." |
| 오래 사는 브랜치 | 오랫동안 병합하지 않고 남아 있는 브랜치 | "오래 사는 브랜치는 마지막에 머지하기가 괴로워요. 하루 이틀 안에 머지합시다." |

## 원격

| 표현 | 뜻 | 예문 |
|---|---|---|
| 올리다, 푸시하다 | `git push` | "다 고치면 올려 주세요. 제가 볼게요." |
| 받다, 풀 받다 | `git pull` | "아침에 먼저 풀 받고 시작하세요." |
| fetch 한번 해 보다 | 병합하지 않고 내려받기만 해서 원격 상황을 본다 | "fetch 한번 해서 origin을 누가 건드렸는지 보세요." |
| 뒤처졌다, 앞섰다 | 내 브랜치가 원격보다 커밋이 적거나 많다(behind, ahead) | "main이 origin보다 커밋 세 개 뒤처졌어요." |
| 강제 푸시, 포스 푸시 | `git push --force`로 원격 기록을 덮어쓴다 | "이미 공유한 브랜치에는 절대 포스 푸시하지 마세요." |
| 레포를 파다 | GitHub에 새 저장소를 만든다 | "이 도구는 레포를 따로 파서 둡시다." |

## 풀 리퀘스트와 리뷰

| 표현 | 뜻 | 예문 |
|---|---|---|
| PR 올리다 | 풀 리퀘스트를 만든다 | "다 고치면 PR 올리고 리뷰어로 저를 지정해 주세요." |
| 리뷰하다 | 다른 사람의 변경을 확인한다 | "이 PR 누가 리뷰해 줄 수 있어요?" |
| 어프루브하다 | 리뷰를 통과시킨다 | "머지하려면 두 명이 어프루브해야 해요." |
| LGTM | Looks Good To Me. 괜찮아 보인다 | "LGTM, 머지해도 돼요." |
| nit | 사소한 지적으로, 안 고쳐도 된다 | "nit: 이 변수 이름은 좀 더 분명하게 할 수 있겠어요." |
| 변경 요청을 받다 | 리뷰어가 고친 뒤에 머지하라고 요구한다(Request changes) | "PR에 변경 요청을 받아서 고치고 다시 푸시할게요." |
| CI가 깨졌다, CI가 빨갛다 | 자동 검사가 통과하지 못했다 | "CI가 깨졌네요. 먼저 어느 테스트가 실패했는지 봐요." |
| 스쿼시하다 | 커밋 여러 개를 하나로 합친다 | "자잘한 커밋은 스쿼시해서 머지하세요." |
| 드래프트 PR | 아직 덜 됐지만 방향을 보여 주려고 먼저 올리는 PR | "방식을 의논하고 싶으니 드래프트 PR부터 올려 주세요." |
| PR을 머지하다 | 병합 버튼을 누른다 | "CI도 통과했고 어프루브도 받았으니 제가 PR 머지할게요." |

## 릴리스

| 표현 | 뜻 | 예문 |
|---|---|---|
| 태그를 찍다 | 어떤 커밋에 버전 태그를 붙인다 | "v1.0.0 태그 찍었어요?" |
| 배포하다, 릴리스하다 | 정식으로 버전을 내보낸다 | "금요일에 배포하니까 목요일부터는 수정만 받아요." |
| hotfix | 릴리스한 버전의 긴급 수정 | "출하한 버전에 문제가 생겼어요. v1.0.0에서 hotfix 브랜치 따서 고칩시다." |
| 코드 프리즈 | 릴리스 전에 새 기능 추가를 멈춘다 | "다음 주에 코드 프리즈라서 새 기능은 다음 버전으로 넘겨요." |
| 버전을 올리다 | 유의적 버전에 따라 번호를 올린다 | "설정 형식이 바뀌어서 호환이 안 되니 주 버전을 올려야 해요." |

## 문제가 생겼을 때

| 표현 | 뜻 | 예문 |
|---|---|---|
| revert하다 | `git revert`로 커밋을 되돌린다 | "이미 푸시했으면 reset 말고 revert하세요." |
| reset으로 되돌리다 | `git reset`으로 브랜치를 과거로 옮긴다 | "아직 안 푸시했으면 바로 앞 커밋으로 reset하면 돼요." |
| stash해 두다 | 커밋하지 않은 변경을 잠시 치워 둔다 | "고치던 건 stash해 두고 버그 수정하러 넘어가세요." |
| reflog를 뒤지다 | `git reflog`로 "사라진" 커밋을 찾는다 | "커밋이 없어졌어요? 당황하지 말고 reflog부터 뒤져 보세요." |
| blame해 보다 | `git blame`으로 어떤 줄을 어느 커밋이 바꿨는지 찾는다 | "이 줄 blame해 보고 왜 바꿨는지 확인해 봐요." |
| 비밀번호가 커밋됐다 | 비밀 정보가 기록에 들어갔다 | "비밀번호가 커밋됐어요. 먼저 비밀번호를 바꾸고, 기록은 그다음에 처리해요." |

"blame"은 원래 "탓하다"라는 뜻이지만, 팀에서는 변경이 어디서 왜 왔는지 찾을 때만 씁니다. 좋은 팀은 이것을 맥락을 이해하는 데 쓰지, 책임질 사람을 찾는 데 쓰지 않습니다.
